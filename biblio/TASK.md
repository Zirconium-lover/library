# Библиографическая база: разрушение циркониевых сплавов с гидридами

Постановка задачи для сессии-библиографа. Заказчик — пользователь, оркестратор — сессия
`session_01Sts5nW3ziAwVguTyuzquvu` (ей отчёт).

## Цель

База **300–500 публикаций** (меньше, если хорошее кончилось раньше; 300 точных лучше 500 шумных) с
**проверенными DOI**, названием, авторами, годом, журналом и коротким содержанием на русском.
Образец формы — каталог пользователя по переориентации гидридов (197 статей; его метаданные —
`biblio/existing_reorientation.csv`). Новая база — про **разрушение**, а не про кинетику выделения.
Годятся и статьи в закрытом доступе: DOI нужен всё равно.

Зачем: на её основе строится мезомодель разрушения (матрица Zr с вязким повреждением и градиентной
регуляризацией, хрупкие гидриды, когезионная граница гидрид–матрица) в форке CalculiX
(репозиторий ccx-arch2), серия расчётов по связности гидридов, перенос между масштабами.

## Жёсткие правила

1. **НИРС не использовать.** Файл `НИРС Ильясов Р.А. М25-109.pdf` в корне library — не источник:
   ни чисел, ни ссылок, ни постановки модели оттуда не брать. Всё, что в `notes/zr-hydride-data.md`
   помечено «НИРС» или «цитата по НИРС» (Kubo 2013 — 710 МПа, Tondro — 30 мкм, свойства Э635
   E 111/108/102 ГПа и σ_y 500 МПа и т. п.), считать **непроверенным**: найти оригинал и взять число из
   него, или не включать.
2. **DOI не выдумывать.** Каждый DOI должен быть виден в источнике, открытом в этой сессии: запись
   Crossref/OpenAlex, страница издателя, результат поиска с этим DOI для этого названия. Не собирать
   DOI по шаблону (например, из номера PII ScienceDirect), если он не подтверждён. Уровень проверки —
   в колонке `doi_check`:
   - `V2` — совпала запись Crossref/OpenAlex или страница издателя (название + год + первый автор);
   - `V1` — DOI виден в результате поиска именно для этого названия.
   Без DOI в основную базу попадают только книги, отчёты и диссертации — с ISBN, URL или handle и
   пометкой `no-doi`. Остальное без подтверждения — в `candidates_unverified.csv`, не в базу.
3. **Числа только с источником и условиями** (материал, температура, метод, единицы) и с пометкой,
   откуда они: `abstract`, `fulltext` или `snippet`.
4. **Без дублей**: DOI в нижнем регистре без `https://doi.org/`; проверять и похожие названия.
5. Пересечение с каталогом пользователя отмечать номером в `overlap_reorient`. Из 197 статей того
   каталога брать в базу только те, что полезны для разрушения (по `existing_reorientation.csv`;
   PDF у пользователя есть).
6. PDF, уже лежащие в корне library (~65 файлов, в основном численные методы), тоже внести в базу
   с именем файла в `pdf_in_library`.

## Направления и подтемы (коды для колонки `subtopics`)

**1. Архитектура проекта: физические модели разрушения, численные приёмы, алгоритмы, решения**
- 1.1 Вязкое разрушение в континууме: CDM (Lemaitre), Rice–Tracey, Johnson–Cook,
  Bai–Wierzbicki / MMC / Hosford–Coulomb, локусы εf(η, θ_Лоде), их калибровка.
- 1.2 Пористая пластичность: Gurson, GTN, Thomason, сдвиговая модификация Nahshon–Hutchinson,
  слияние пор, нелокальный GTN.
- 1.3 Регуляризация и масштаб: crack band, нелокальная интегральная, неявная градиентная,
  over-nonlocal, микроморфная, localizing gradient, фазовое поле для вязкого разрушения,
  идентификация внутренней длины ℓ, объективность по сетке, масштабный эффект (Bažant).
- 1.4 Когезионные зоны: законы (билинейный, экспоненциальный, PPR), смешанный режим (B-K),
  штрафная жёсткость и искусственная податливость, вязкая регуляризация, кинематика при больших
  поворотах, вставка элементов, intrinsic/extrinsic.
- 1.5 Хрупкое разрушение включений в объёме: критерий по главному напряжению, crack band для
  хрупкой фазы, статистика прочности (Вейбулл), растрескивание частиц в пластичной матрице.
- 1.6 Численные алгоритмы: IMPL-EX, path-following / arc-length (в т. ч. по диссипации),
  line search, staggered и monolithic, согласованные касательные, удаление элементов, контакт
  берегов трещины, переход континуум → разрыв (XFEM/GFEM/embedded), адаптивность сетки.
- 1.7 Микромеханика и RVE материалов с включениями и межфазной границей: отслоение плюс
  повреждение матрицы, гомогенизация разупрочнения, размер RVE, граничные условия.
- 1.8 Верификация и бенчмарки: Sandia Fracture Challenge, эталоны для когезии и нелокальных моделей.

**2. Физика разрушения циркониевых сплавов с гидридами (параметры, экспериментальные данные)**
- 2.1 Свойства гидридов: упругость (эксперимент и DFT), твёрдость, K_IC, прочность, пластичность,
  зависимость от температуры, размерный эффект, микроконсоли и микростолбы.
- 2.2 Граница гидрид–матрица: микромеханические испытания, работа разделения (DFT/MD), отслоение,
  поры на границе.
- 2.3 Матрица: упругопластичность, анизотропия (Hill), упрочнение до больших деформаций,
  локус εf(η, θ), надрезанные и сдвиговые образцы; Zry-2/-4, ZIRLO, M5, Э110, Э635, Zr-2.5Nb;
  20–400 °C; облучение — кратко.
- 2.4 Механизмы разрушения гидрированных сплавов: скол гидрида, зарождение пор, перемычки,
  полосы сдвига; in situ SEM / DIC / EBSD / томография / синхротрон; деформация растрескивания
  гидридов.
- 2.5 Испытания гидрированных оболочек: сжатие и растяжение колец, burst, EDC, вязкость
  разрушения (PLT и др.), вязко-хрупкий переход; влияние доли, длины, связности радиальных
  гидридов, ободка, блистеров.
- 2.6 Деформация превращения и остаточные напряжения вокруг гидридов.
- 2.7 Морфология и меры связности (RHCF, Fn, HCC, пути), анализ изображений, 3D-реконструкции.
- 2.8 DHC — только как разрушение гидрида у вершины трещины (K_IH, критический размер).

**3. Существующие модели разрушения Zr с гидридами**
- 3.1 Явные гидриды в МКЭ: 2D/3D микромеханика, когезия, XFEM, фазовое поле, кристаллическая
  пластичность с гидридами.
- 3.2 Континуальные модели повреждения гидрированного Zr (анизотропные, GTN с H и т. п.).
- 3.3 Перколяция, критический путь, стохастические (морфология Монте-Карло + разрушение),
  машинное обучение для пластичности.
- 3.4 Механика разрушения и инженерные критерии для радиальных гидридов; модели DHC.
- 3.5 Топливные коды (BISON, FRAPCON/FALCON, TRANSURANUS, отечественные) — модули отказа
  оболочки по гидридам, кратко.

Ориентиры по объёму: направление 1 — 150–220, 2 — 150–220, 3 — 50–100. Русскоязычные работы по
Э110/Э635 (ВАНТ, «Атомная энергия», ФММ, «Цветные металлы», Physics of Atomic Nuclei, «Вопросы
материаловедения», диссертации) — обязательно, с DOI, где он есть.

## Затравка для «снежного кома»

DOI ищите сами; из затравки берите списки литературы и цитирующие работы.
- Направление 1: Bažant & Oh 1983 (crack band); Bažant & Jirásek 2002 (nonlocal survey);
  Peerlings et al. 1996 (gradient enhanced damage); Jirásek & Bauer 2012 (crack band numerics);
  Engelen, Geers, Baaijens 2003; Poh & Sun 2017; Besson 2010 (review of continuum ductile fracture);

  Turon et al. 2006, 2007; Benzeggagh & Kenane 1996; Segurado & LLorca 2004; Oliver, Huespe,

  Ambati, Gerasimov, De Lorenzis 2015 (phase-field ductile).
- Направления 2–3: Chan, Roberts, Gong 2016 (микроконсоли гидрида и границы); Kolesnik 2024,
  Eng. Fail. Anal. (обзор механизмов вязко-хрупкого перехода, >100 экспериментов — главный источник
  ссылок); Motta et al. 2019 (Hydrogen in zirconium alloys: a review); Puls 2012 (книга); Le Saux и

  превращения); Aliev & Kolesnik 2023 (3D Монте-Карло морфологии).

## Инструменты и доступ

- **WebSearch** работает — основной инструмент на старте.
- **API OpenAlex / Crossref / doi.org** сейчас закрыты сетевой политикой среды (прокси отвечает 403).
  Пользователь может их открыть. В начале попробуйте один раз:
  `curl -sS -m 15 "https://api.openalex.org/works?search=zirconium%20hydride&per-page=1"`.
  Если 403 — не повторяйте, работайте через поиск и ставьте `V1`. Если открыто — используйте
  OpenAlex для массовой проверки (`V2`) и «снежного кома» (`referenced_works`, `cited_by`).
- **ScienceDirect через браузер пользователя** из облачной сессии недоступен: это делает отдельная
  сессия на компьютере пользователя. Для неё ведите `needs_fulltext.csv`: что именно достать из
  полного текста (таблицы параметров, кривые, условия, подтверждение DOI).

## Что сдать (ветка `claude/ccx-arch2-damage-cohesion-lsehkr-biblio` репозитория library)

- `biblio/catalog.csv` — основная таблица, UTF-8, модуль csv Python. Колонки:
  `id, direction, subtopics, year, title, authors, journal, type, doi, doi_check, access,
  summary_ru, useful_for, values, values_source, priority, overlap_reorient, pdf_in_library, url,
  notes`
  - `direction`: 1, 2, 3 или несколько через `;`.
  - `type`: эксперимент / модель / численный метод / обзор / данные / книга / диссертация.
  - `access`: OA / closed / ?.
  - `summary_ru`: 2–4 предложения — что сделано, главный результат, чем полезно нам.
  - `useful_for`: конкретно — какой параметр, закон или алгоритм.
  - `values`: для направления 2 — числа с единицами и условиями.
  - `priority`: A — читать или достать PDF первым, B — полезно, C — фон.
- `biblio/catalog.xlsx` — собирается скриптом `biblio/build_xlsx.py` из CSV. Листы:
  - «Реестр» — как у пользователя: №, Год, Название, Направление/подтемы, Краткое содержание,
    Авторы, Журнал, Тип, DOI, Доступ, Приоритет, Что берём для модели, Значения;
  - «Темы» — подтема, что искать, число статей;
  - «Параметры» — строки значений направления 2: параметр, значение, единицы, условия, материал, id;
  - «Сводка» — счётчики.
- `biblio/needs_fulltext.csv` (`id, doi, title, what_to_extract`), `biblio/candidates_unverified.csv`.
- `biblio/README.md` — метод, поисковые запросы, статистика (сколько по направлениям, доля V1/V2).

## Порядок работы

- Партии по 25–50 записей по подтемам. После каждой партии — дописать CSV, commit, push. Работа
  должна переживать лимиты и перезапуски: состояние только в файлах.
- Держите свой контекст маленьким: длинные выдачи поиска пишите в файлы, а не в разговор. Для
  параллельного поиска по подтемам можно запускать субагентов, которые возвращают строки CSV;
  дедупликацию и запись делает основная сессия.
- Отчёт оркестратору (`send_message` в `session_01Sts5nW3ziAwVguTyuzquvu`) — примерно через каждые
  100 записей, коротко: счётчики по направлениям и подтемам, доля V1/V2, пробелы. Не после каждой
  партии.
- Остановка: достигнут объём или насыщение (новые поиски дают меньше 10 % новых полезных записей).
